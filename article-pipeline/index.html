# 素材底稿

文章生成流水线是一套以 Markdown 为核心的文章生产工作流。

系统目标是把原始素材转成：
- 一份可继续编辑的 Markdown 主稿
- 一份可直接分享的 HTML 成品

核心流程：
1. 统一整理原始素材
2. 规划文章类型、读者与结构
3. 用 Markdown 完成正文起稿
4. 渲染生成 HTML
5. 分开检查内容与展示
6. 只修最小失败单元

支持的文章类型：
- 解释型
- 教程型
- 评测型
- 简报型
- 长文型

核心设计原则：
Markdown 是内容真身，HTML 是展示层。

写作规划

生成前先写规划文档，明确文章类型、结构、保留策略和审查重点。

# 写作规划

## 文章类型
解释型

选择原因：
这份素材的目标是介绍一套系统及其设计逻辑，所以核心任务是把它讲清楚。

未选择的相近类型：
- 教程型：它不是操作步骤说明
- 评测型：它不是以比较和评价为核心

## 目标读者
面试官、工程师，以及希望快速理解系统结构的产品型读者。

## 信息保留策略
中高保留。
保留流程、文件结构和设计决策。
压缩重复解释。

## 核心结论
文章生成流水线把一次性提示词生成文章，变成了一套受控的生产流程。

# 文章生成流水线

文章生成流水线是一套通用文章生产工作流。它不依赖一次性提示词，而是把整个过程拆成素材整理、规划、起稿、渲染、审查和修补。

## 为什么 Markdown 优先

核心设计决策是让 Markdown 成为内容真身。这样文章既可编辑，也可迁移，还可以复用于不同发布环境。

## 从素材到交付

这套流程会先把原始素材整理成稳定事实底稿，再生成规划文档，明确文章类型、读者、保留策略和结构，然后才开始写正文主稿并渲染成 HTML。

## 为什么它是流程框架

这套系统不只是生成文字，它通过中间状态文件、审查步骤和修补规则来管理整个生成过程。

成品渲染

article.html 由 article.md 渲染生成。HTML 层负责目录、摘要区、代码高亮和排版增强，但不改写正文结构。

分开两层审查
